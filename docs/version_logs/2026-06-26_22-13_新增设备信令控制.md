# 2026-06-26 22:13 新增设备信令控制

## 本次修改目标

根据胡师兄提供的 `README_device_signal.md`，在传感器数据测试页中集成设备信令控制功能，支持设备自检、编码器复位、单独进入手动模式、单独进入自动模式。

## 修改了哪些文件

- `app/src/main/java/com/example/mavlinktest/SensorDataTestActivity.kt`
- `app/src/main/res/layout/activity_sensor_data_test.xml`
- `app/src/main/res/layout-sw600dp/activity_sensor_data_test.xml`

## 每个文件主要改了什么

### SensorDataTestActivity.kt

- 新增信令接口常量：
  - `http://36.133.42.8:8119/api/gather/signalling/sendSignalling`
  - `F3` 设备自检
  - `F9` 编码器复位
  - `FC/00` 进入手动模式
  - `FC/01` 进入自动模式
- 新增独立 `signalExecutor`，避免设备控制请求阻塞原有数据拉取。
- 新增“手动模式 → 功能指令 → 自动模式”的三步执行流程。
- 新增复选框控制逻辑：勾选时自动切换模式，不勾选时只发送功能码。
- 新增单独进入手动模式和进入自动模式的按钮逻辑。
- 信令接口复用原传感器页的 `accessToken`，必要时自动认证。
- 信令执行过程中禁用相关按钮，并通过状态文字和 Toast 提示结果。

### activity_sensor_data_test.xml

- 在手机布局中新增设备控制区域。
- 新增按钮：
  - 设备自检
  - 编码器复位
  - 进入手动
  - 进入自动
- 新增自动切换复选框和设备控制状态显示。

### layout-sw600dp/activity_sensor_data_test.xml

- 在平板布局中新增横向设备控制区域。
- 保持按钮、复选框、状态显示与手机布局一致，同时减少对曲线和列表区域的占用。

## 是否新增功能

是。新增设备信令控制功能，可在 Android 端直接发送设备自检、编码器复位和模式切换指令。

## 是否修复 bug

否。本次是新增功能，没有针对现有缺陷做专项修复。

## 是否还有遗留问题

- 需要在真实网络和设备环境下确认 `8119` 信令接口是否可达。
- 需要确认设备收到 `F3`、`F9`、`FC/00`、`FC/01` 后的实际动作是否与师兄定义一致。
- 如果现场要求更细的执行日志，后续可以把每一步接口返回原文也显示出来。

## 如何运行或测试这个版本

1. 在 Android Studio 中运行或安装 Debug APK。
2. 打开主界面，点击右上角“传感器”进入传感器数据测试页。
3. 确认检测编号已填写，例如 `006A0001`。
4. 点击“认证”获取 Token，或直接点击设备控制按钮，程序会在需要时自动认证。
5. 点击“设备自检”或“编码器复位”，默认执行“进入手动 → 等待 3 秒 → 发送功能 → 等待 3 秒 → 返回自动”。
6. 取消勾选“执行时自动切换：手动 → 功能 → 自动”后，再点击功能按钮，将只发送对应功能码。
7. 本地已执行 `.\gradlew.bat :app:assembleDebug --no-daemon --stacktrace`，编译通过。
